# 导出

把资料库里的书**写成文件**，并可以降级成纯文本。

这是项目里唯一一处「输出」——此前所有数据都只进不出。

---

## 一、它是什么，不是什么

**是**：把书的本体导出到你选的文件夹；可以把能转的格式降级成 `.txt`。

**不是**：格式互转。TXT 不会变成 PDF，PDF 不会变成 EPUB，EPUB 不会变成 PDF。要做到那些，需要 PDF 生成器或 EPUB 打包器，是另一个量级的工作。

也不是**备份/恢复**：导出不带 `library.json`，不保留 UUID，导出的文件重新导入会变成新条目、丢失阅读进度。整库备份是未来独立的功能。

---

## 二、两种目标

| 目标 | 做什么 | 支持范围 |
|---|---|---|
| **原始文件** | 把托管副本原字节拷出来，沿用原扩展名 | 全部格式 |
| **纯文本 .txt** | 解码 / 抽取正文，丢掉样式 | TXT 系、PDF、EPUB |

音频没有文本表示，所以「纯文本」对音频置灰并给出原因——而不是等到写完才发现是空的。

---

## 三、转换的真相：都是降级

三种转换的信息损失程度完全不同，代码里也如实写明了。

### 文本系 → 文本

无损。后端用与查看器相同的规则解码（BOM → UTF-8 → GB18030），导出即原样写回。换行不做规范化——导出 `.txt` 就该得到那个 `.txt`。

### EPUB → 文本（质量最好）

EPUB 自带 spine 顺序和目录，所以标题层级是**真的**，不是从字号猜的。

复用 `viewers/epub/package.ts` 的解析（`readContainer` / `readPackage` / `flattenToc`），一行没改。这是把解析和渲染分开的回报——导出只是第二个消费者。

输出带 Markdown 标题标记（`#`），在 `.txt` 里不碍事，在支持 Markdown 的地方又能保留层级。

**丢掉**：排版、字体、图片（保留 `[图：alt]` 占位）、脚注链接。

### PDF → 文本（有损，必须承认）

PDF 没有阅读顺序，只有坐标上的字形。能救回的是每页的文字流，按 y 坐标分行、按 x 排序重组。救不回的是版面、图片、表格、分栏。

因此：

- **保留页码分隔**（`── 第 N 页 ──`）。对照原文时页码是唯一锚点；没有它，300 页就是一面墙。
- **不做段落推断**。空行启发式是猜，猜错会把不相关的章节并到一起。
- **扫描件输出为空**，此时不写零字节文件，而是报「转换结果为空，可能是扫描件或不含文字」。

## 四、架构：又一个注册表

和查看器完全同构。外壳不认识任何具体格式。

```ts
// src/export/registry.ts
registerConvertTarget({
  id: 'markdown',           // 未来
  label: 'Markdown .md',
  extension: 'md',
  supports: ['epub', 'txt'],
  convert: async (input) => { ... },
})
```

加一种目标格式 = 注册一个描述符。资料库页面、store、管线都不用改。

`original` 是唯一的特例：它没有 `convert`，管线直接拷字节。把它放进注册表是为了让菜单、store、管线用同一条路径处理它。

### 管线：先转完，再写盘

```
选中条目
  → 逐条转换（记录失败）
  → 全部转完后，一次性交给 Rust 写盘
```

反过来做（转一条写一条）会在第 7 条出错时留下半批文件，而人无从判断哪些是好的。

失败只收集不抛出：一本坏书不该取消其余九本。

---

## 五、写盘：Rust 侧的三条铁律

前端负责转换（它才有 PDF/EPUB 引擎），Rust 负责落盘。字节跨 IPC，不传源路径——这样畸形调用无法让后端读取任意位置。

### 1. 绝不覆盖

两本书可以同名。静默替换已有文件就是数据丢失。冲突时递增成 `name (2).ext`、`name (3).ext`，到 999 报错。

同一批内也要去重：第二个同名文件还没落盘，文件系统查不到它，所以用一个 `HashSet` 记住本批已占用的名字。

### 2. 消毒文件名

`title` 来自文件名，可能含 `: * ? " < > |`、首尾空格和点、Windows 保留名（`CON`、`NUL`）。前后端各做一遍：前端做是为了让用户提前看到结果，Rust 做是因为**它才是真正碰文件系统的那个**，不能信任跨 IPC 传来的任何东西。

### 3. 原子写

`.tmp` + rename。中断只留旧文件或新文件，不会是半个。

## 六、界面

资料库头部右侧 `...` → `导出` → 选目标格式 → 进入选择模式。

- 每行左侧出现复选框；不支持当前格式的行置灰且复选框禁用
- 头部换成选择工具栏：`已选 3 / 共 5`、全选、清除、取消、导出
- 此模式下「移除」隐藏——误点会删掉正要导出的文件
- Esc 退出（`preventDefault`，不抢外壳的返回）

结果用一条可关闭的横条反馈，与 `ImportFeedback` 同形。部分成功是警告色而非成功色：有人要求的事没发生。

**不做假数据**：数字全部来自 Rust 实际返回。

## 七、明确不做

| 不做 | 原因 |
|---|---|
| TXT → PDF | 需要 PDF 生成器，是新依赖 |
| TXT → EPUB | 需要写 ZIP + OPF |
| PDF → EPUB | 版面重建，不现实 |
| `.ltxt` 自定义格式 | 暂缓；注册表已留好位置 |
| 整库备份 / 恢复 | 独立功能，涉及 `library.json` 打包与版本迁移 |
| 导出进度条 | 用 `已转换 N / M` 文本；条目通常不多 |
| 后台队列 / 断点续传 | 过度设计 |

## 八、已知限制

| 限制 | 影响 | 可能的解法 |
|---|---|---|
| 大文件整块过 IPC | 28 MB 的 EPUB 转文本要几秒，期间无进度条 | 改成分批或 Rust 侧直接读 |
| PDF 扫描件 | 导出空文件 → 报「结果为空」 | 需要 OCR，不在此项目范围 |
| PDF 双栏 | 可能串行 | 需要版面分析 |
| 文件名长度 | 截断到 80 字符 | 可提示用户 |
| 进度不跟随导出 | 导出不改阅读进度 | 设计如此 |
