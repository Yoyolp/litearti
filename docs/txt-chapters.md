# TXT 分章

本地 `.txt` 小说常常是一整个文件，章节标题就写在正文里。识别出这些标题后，阅读器可以一章一屏、带目录、记住读到第几章，而不是让你滚动一个几兆的文本。

---

## 一、原则：宁可少切，不可错切

误判的代价不对称：

- **错切**（把正文当标题）：一章从句子中间开始，读者看到的是残句，比不分章更糟
- **漏切**（没识别出标题）：保持整篇滚动，和原来一样，没有损失

所以每条规则都偏向"这不是标题"。

## 二、识别规则

一个行要成为章节标题，必须同时满足：

1. **从行首开始**（`第一章` 前面只有空白）
2. **整行不超过 40 字** —— 标题是标题，不是段落
3. **匹配编号格式**：
   - 中文：`第 <数字> <章|节|回|卷|集|部|篇>`，数字可以是 `1`、`１２`、`一`、`百二十三`
   - 英文：`Chapter 1`、`Part IV`
4. **单位字后面必须是空白、分隔符或行尾**

第 4 条是关键。它让这些**不会**被误判：

| 行 | 为什么不算 |
|---|---|
| `第一节课上，老师讲了很多。` | `课` 不是单位字 |
| `第二天，他走了。` | `天` 不是单位字 |
| `第三章讲的是这个道理。` | `章` 后面直接接 `讲`，没有分隔 |
| `第十个人` | `个` 不是单位字 |
| `第一章 少年。` | 以句号结尾，是句子不是标题 |

## 三、阈值

少于 **3 个**标题的文件不当作分章小说。两处匹配在几十万字的文件里几乎必然是巧合。

## 四、前言的处理

第一个标题之前的内容：

- 超过 20 字 → 作为「前言」一章保留（通常是简介、作者的话）
- 不足 20 字 → 丢弃（只是书名和作者行，单独成章会是一片空白）

## 五、识别不到时

完全不改变行为：整篇连续滚动，滚动位置按比率记忆。和加这个功能之前一模一样。

界面上的差别只有一处：有章节时才出现目录按钮和章节导航。

## 六、进度的兼容

老版本存的是整篇的滚动比率。分章后需要的是章号，所以：

- 有 `chapter` 字段 → 直接用
- 只有 `ratio` → 按行位置映射到对应章节，读者大致停在原来的地方
- 都没有 → 从第一章开始

不会因为加了分章就把老读者扔回开头。

## 七、明确不做

| 不做 | 原因 |
|---|---|
| 按字数自动切分 | 会切断句子，破坏叙事 |
| 识别无编号的标题（如单独一行的短句） | 误判率太高 |
| 支持自定义分章正则 | 需要一套配置界面；现有规则覆盖绝大多数中文小说 |
| 修改原文件 | 分章只是渲染时的视图，`.txt` 一个字节都不动 |
