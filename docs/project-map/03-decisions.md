# 决定记录：为什么这么做，拒绝了什么

> **审计时最重要的文件。**
>
> 代码里看起来奇怪的地方，多半是为了修一个真实 bug 才变成那样的。改之前先在这找一找。
>
> 每条都写了**被拒绝的替代方案**。没写拒绝了什么的决定，大概还没被真正想过。

---

## 一、视觉与设计

### 1.1 没有品牌色

**决定**：整套界面灰度，层次只由间距/尺寸/对比度/字重建立。唯一的彩色是语义色（危险/警告），面积小、饱和度低。

**拒绝了**：
- ❌ 主色 + 强调色（"按钮不突出就变蓝"）—— 一旦有主色，人就会用它解决所有问题，界面变成一堆色块，层次反而消失
- ❌ 给设置页单独做彩色（有一张参考图是绿/青大色块）—— 只有一页彩色，其他页会显得没做完

**代价**：卡片在 `#fafafa` 上用 `#ffffff` 只有 1.02:1 对比度，**几乎看不见**。所以卡片必须带 `--shadow-e1`。这是实测发现的，不是审美选择。

**在哪里**：`src/styles/tokens.css`、`docs/design-system.md`

---

### 1.2 不用 UI 组件库

**决定**：手写全部组件，视觉由 token 长出来。

**拒绝了**：
- ❌ Element Plus / Naive UI —— 会带来它们的设计语言，与本项目的灰度层次冲突；而且包体积远大于全部视图之和

**代价**：每个控件都要自己写（下拉、滑块、对话框）。但换来的是没有一处"这是库默认样式"的妥协。

---

### 1.3 封面：本地书排版生成，发现页加载远程图

**决定**：两个例外规则共存。

| 场景 | 做法 |
|---|---|
| 本地文件卡片 | 排版书脊（`--surface-sunken` + 格式名 + 三行标题） |
| 发现页番剧卡片 | 加载远程封面，失败回落文字色块 |

**拒绝了**：
- ❌ 本地书也接豆瓣/OpenLibrary 封面 —— 一个"阅读不联网"的应用为此联网，而且书名匹配经常错
- ❌ 发现页也不加载封面 —— 时间表本身就只有封面和标题，不给封面等于废掉一半

**为什么能共存**：那条"不加载外部封面"的规矩是为本地书架定的（本地文件本来就没有封面）。番剧的封面就是它的识别特征，情况不同。

**在哪里**：`docs/design-system.md` §14.1.1

---

## 二、进程与边界

### 2.1 网络只走 Rust

**决定**：前端一行 `fetch(` 都没有。

**拒绝了**：
- ❌ 前端直接 `fetch` —— 源站点几乎全部没有 CORS 头，会被浏览器拦

**副作用（好的）**：只有 4 个模块需要审网络行为。

**在哪里**：`net.rs`、`stream.rs`、`bangumi.rs`、`rules_mirror.rs`

---

### 2.2 Tauri 只在适配层

**决定**：只有 4 个文件 import `@tauri-apps/*`。

**拒绝了**：
- ❌ 视图直接 `invoke` —— 桌面→移动迁移时每个视图都要改

**历史教训**：`SourcesView.vue` 曾经自己 import 对话框插件。这是真实泄漏，已修。**审计时如果发现第 5 个文件 import Tauri，说明边界在被侵蚀。**

---

### 2.3 规则镜像编在 Rust 里

**决定**：前端只传镜像 id（`gitcode` / `ghproxy` / `github`），base URL 编在 Rust。

**拒绝了**：
- ❌ 前端传完整 URL —— 那这个命令就成了通用代理，可以请求任意地址

**同类决定**：`proto.rs` 只服务 `main` 窗口、`stream.rs` 只允许 http(s)、`bangumi.rs` 只请求固定镜像。

**共同理由**：任何"接受 URL 参数的命令"都是从受限能力退化成通用能力的口子。

---

## 三、数据模型

### 3.1 资料库混装两类条目

**决定**：`Entry.kind: 'file' | 'online'`，一个列表，用筛选区分。

**拒绝了**：
- ❌ 两份存储（`library.json` + `online.json`）—— 筛选/排序/搜索要各实现一遍，容易不一致
- ❌ 做成两个页面/子栏 —— 人想的是"我能打开的东西"，不是"文件和引用"

**代价**：`Entry` 不再是纯文件模型，文件字段对 online 条目是空值。

**兼容性**：所有新字段带 `#[serde(default)]`，旧 `library.json` 原样加载。

---

### 3.2 番剧进度：一份还是两份

**决定**：
- 未加入资料库的临时观看 → `localStorage`（`litearti.anime-progress`）
- 加入资料库之后 → `Entry.progress` 是**唯一真相**

**拒绝了**：
- ❌ 两份同时存在 —— 会出现"资料库说第 3 集，播放器说第 5 集"

**注意**：这个迁移逻辑目前是"加入后以 Entry 为准"，未做自动搬迁。**审计时可以查这一点**：如果两边都写，就是 bug。

---

### 3.3 localStorage 与磁盘的分界

**决定**：内容进磁盘文件，界面偏好进 localStorage，可重建的进缓存文件。

**拒绝了**：
- ❌ 全放 `library.json` —— 主题列表一变就要迁移库文件，而库文件是用户的珍贵数据

**在哪里**：`02-architecture.md` §5 有完整对照表。

---

### 3.4 阅读偏好只有一份

**决定**：`library/readingPrefs.ts` 是唯一来源，两个阅读器都读它，**都不保留本地副本**。

**拒绝了**：
- ❌ 每个阅读器自己 `ref(17)` —— 这正是之前的 bug：源阅读器的字号不持久化，本地阅读器完全没有，而设置页会显示一个实际不生效的值

**历史**：`TextReader` 曾把 `fontSize` 存进每个条目的 `progress` 里，导致每本书字号不同。旧字段保留但不读回——读回会悄悄改掉其他书的设置。

## 四、匹配与解析

### 4.1 两个不同的标题匹配策略（有意不一致）

| 场景 | 策略 | 为什么 |
|---|---|---|
| 跨源重匹配 | **完全相等**（标准化后） | 会**覆盖**已有条目指向的源，配错会让人看错一整集 |
| 发现 → 源搜索 | **相似度**（Dice 0.6） | 只打开一个搜索结果，最坏是多一个错结果 |

**拒绝了**：
- ❌ 统一用相似度 —— 重匹配会静默改数据
- ❌ 统一用完全相等 —— Bangumi 写「孤独摇滚！」，源站写「孤独摇滚 第一季」，会漏掉绝大部分

### 4.2 剥离续作标记（修了一个真实 bug）

**问题**：原始 Dice 系数对**更短的后缀惩罚更小**，所以：

```
目标「进击的巨人」
  0.800  进击的巨人 中学      ← 恶搞番外，排第一
  0.727  进击的巨人 第一季    ← 正片，排第二
```

自动选中会把用户带进错误作品。

**修复**：打分前剥掉 `第X季` / `第X期` / `最终季` / `Season N` / `第N部分`，但**不剥** `剧场版` / `番外` / `OVA` / `中学`（那些是不同作品，剥了会和正片打平）。

**已知无法区分**：`钢之炼金术师` 与 `钢之炼金术师 FA` 相似度 0.83，没有阈值能分开。靠平局规则：按源站搜索结果原顺序取第一个。

**在哪里**：`src/discover/match.ts`、`scripts/verify-bgm-match.mjs`

---

### 4.3 Bangumi 解析在 TypeScript，不在 Rust

**决定**：Rust 只返回 JSON **文本**，解析在 `src/discover/subject.ts`。

**原因**：两个端点字段不一致——
- `calendar/season` 返回 `{ "1": [{subject}] }`，`rating.count` 是**对象**
- `popular/subjects` 返回 `{ data: [subject] }`，`rating.count` 是**数组**，且**没有 `date`**

**拒绝了**：
- ❌ Rust 解析一份 + TS 解析一份 —— 两个会漂的地方

**验证**：`scripts/fixtures/bgm-*.json` 是**真实抓取**，`verify-bgm-parse.mjs` 用它们测。手写 fixture 只能证明"解析器能解析作者想象中的结构"。

## 五、网络与安全

### 5.1 cookie 不进 URL

**决定**：流代理只接受 `s=<sourceId>`，cookie 由 Rust 查库附上。

**拒绝了**：
- ❌ `?c=<cookie>` —— cookie 会进 devtools、日志、浏览历史

**配套约束**：精确 host 匹配（子域名不继承）、跨 host 重定向时被 `reqwest` 剥离（有测试固定）、没有任何命令把 cookie 交给前端。

**改变了既有承诺**：`docs/stream-proxy.md` 原来写"不维持 cookie"。改成了"按源声明查"，并在文档里公开说明——这条改动不能悄悄做。

---

### 5.2 自定义 scheme 只服务主窗口

**决定**：`proto.rs` 检查 `context.webview_label() == "main"`，否则 403。

**这是个安全修复，不是诊断**。`register_asynchronous_uri_scheme_protocol` 是**应用级**注册，任何窗口都能访问。没有这个检查，一个加载远程页面的窗口（登录窗口、嗅探窗口）能把代理当 SSRF 客户端，带着 cookie 请求任意 URL 并读回响应。

**查证过程**（不能靠猜）：逐层追源码确认 `UriSchemeContext::webview_label()` 就是窗口 label，然后运行时打印验证（实测返回 `"main"`）。记录在 `docs/sniffing.md` §2。

---

### 5.3 JS 沙箱

**决定**：`@js:` 选择器在 `sandbox="allow-scripts"`（**无** `allow-same-origin`）的 iframe 里跑，3 秒超时。

**为什么不能加 `allow-same-origin`**：那样 iframe 就能摸到父页面和 `__TAURI_INTERNALS__`，等于把整个应用交出去。

---

### 5.4 封面：负缓存是必需的

**决定**：下载失败也记 1 小时，不重试。

**原因**：Bangumi 图床在部分网络不可达。不缓存失败的话，24 张卡片每次渲染各发一次注定失败的请求。

**实测效果**：同一张封面第二次调用从 **10024ms → 6ms**。

**拒绝了**：
- ❌ 只缓存成功 —— 这正是改动前的状态，等于每次渲染都在等超时

---

## 六、播放

### 6.1 用 WebView `<video>` + hls.js，不用 mpv

**决定**：`<video>` + hls.js（动态 import）。

**拒绝了**：
- ❌ mpv / libmpv —— 要打包解码器，体积和跨平台成本都高

**代价（明确接受）**：
- 编码支持取决于系统 WebView2
- **没有解码器可选**（这正是 Kazumi 有多种硬解选项的原因：它的 mpv 后端按平台不同）
- 没有 Anime4K 超分
- 截图困难（跨源视频帧会污染 canvas）

### 6.2 `canPlayType(...) === 'probably'` 是唯一可信的原生 HLS 信号

**坑**：WebView2 的 `canPlayType('application/vnd.apple.mpegurl')` 返回 `'maybe'`，但 Chromium **没有** HLS 解复用器。用 `!== ''` 判断会走原生路径，结果黑屏 + `video.error.code === 4`。

**决定**：只有 `=== 'probably'` 才算支持原生 HLS。

**在哪里**：`AnimePlayerView.vue`、`verify-stream-playback.mjs`（同一断言）

### 6.3 `kazumi-stream://` 的 origin 因平台而异

**坑**：Windows 上 Tauri 把它服务在 `http://kazumi-stream.localhost`，macOS/Linux 是 `kazumi-stream://localhost`。写死一种会在另一个平台报 `Failed to fetch`。

**决定**：`src/sources/stream.ts` 的 `streamOrigin()` 按平台返回，测试探测两种形式。

### 6.4 XPath 属性语法用 `/::attr()` 不用 `@href`

**原因**：`@` 已经是 XPath 的谓词语法（`//div[@class='x']`）。用 `@href` 会歧义。所以定义成 `/::attr(href)`。

**容错**：`splitXPathAttribute` 容忍 `//::attr()` 和结尾斜杠。

## 七、嗅探

### 7.1 用 CDP 而不是 JS 注入

**决定**：`Network.requestWillBeSent`。

**拒绝了**：
- ❌ 页面内注入脚本 —— **看不到跨域 iframe**，而需要嗅探的站点几乎都把播放器放在 iframe 里

**代价**：Windows 独有（WebView2 有 CDP，WebKitGTK/WKWebView 没有）。

---

### 7.2 嗅探窗口可见但移出屏幕

**决定**：`visible(true)` + 位置 `(-20000, -20000)`。

**拒绝了**：
- ❌ 隐藏窗口 —— WebView2 对不可见窗口做节流，页面可能**根本不加载视频**，症状是"有时候能嗅到有时候不能"，最难查的一类

---

### 7.3 等满超时，不首命中即停

**决定**：收集 12 秒，收集全部候选，再挑。

**拒绝了**：
- ❌ 拿到第一个 `.m3u8` 就收工 —— **前贴片广告通常就是第一个 HLS 请求**

---

### 7.4 嗅探失败只给简单提示

**决定**：停在剧集列表，给一句说明，「访问网站」按钮仍可用。不重试、不弹模态框。

**来源**：用户明确表达过"能用就用，不能用就算了，如果没源可用那这个就是首选"。

---

### 7.5 `sniff/pick.rs` 是纯函数

**决定**：判断层（哪个 URL 该播）与采集层（开窗口听 CDP）完全分离。

**为什么**：判断层是 bug 密集区（"200 个请求里哪个是视频"），把它做成纯函数就能用普通数据测试，不需要浏览器。

**采集层没有单元测试**（真实缺口）：`sniff/windows.rs` 的 COM 初始化会让 `cargo test` 二进制在**加载期**崩（`0xC0000139`），连 `--list` 都不行。所以用 `#[cfg(all(target_os="windows", not(test)))]` 排除，唯一覆盖是 `verify-sniff.mjs` 端到端脚本。

---

## 八、测试策略

### 8.1 测行为，不测实现；跑真实代码，不重写

**决定**：`verify-*.mjs` 用 esbuild 把**真实的 TS 模块**打包出来在 Node 跑。

**拒绝了**：
- ❌ 在测试里复制一份逻辑 —— 测的是复制品的正确性，不是产品的
- ❌ 用 shim 遮住被测行为 —— 遮住了就什么都没测到

**`verify-video-engine.mjs` 的教训**：曾尝试在 Node 里 shim `XPathResult`，失败后改成 esbuild 打包 engine 注入应用 webview 里跑。

### 8.2 fixture 必须是真的

**决定**：`scripts/fixtures/` 里是真实抓取的页面和 JSON。

**为什么**：手写 fixture 会让测试永远绿，而真实 API 已经改版。

**代价**：真实 fixture 会过期。`bgm-calendar.json` 是某一季的，下一页要重新抓。

### 8.3 断言不变式，不猜具体值

**例子**：
- 番剧数量断言 `> 50` 而不是 `=== 80`（下一季就变了）
- 布局断言最小宽度、不重叠，而不是"700px 宽时正好 3 列"（那是算术，不是设计意图）

**教训**：曾经断言"700px 至少 3 张卡"，算一下 `700 - 208 侧栏 - 48 padding` 只能放 2 列 148px 的卡。断言错了，不是布局错了。

### 8.4 界面测试要跑真实 UI

**决定**：CORS/交互类测试通过 CDP 驱动真实应用，不 mock。

**关键例子**：`verify-library-online.mjs` 走**真实的「加入资料库」按钮**。直接调 IPC 命令会绕过当初出问题的 store 更新，在 bug 还活着时也能通过。

## 九、其他

### 9.1 看板删除，统计条保留

**决定**：独立的「看板」页删除，四个数字挪到资料库顶部。

**拒绝了**：
- ❌ 保留看板的格式分布/状态分布/最近列表 —— 和一个可筛选的列表重复了，两个入口看同一件事

**「本周新增」被删掉**：它算的是"打开次数"，对阅读来说不是有意义的数字。**看起来有意义但其实没有的数字，比没有数字更糟。**

### 9.2 设置页：左分类 + 右卡片

**决定**：两个分类栏 + 内容卡片，卡片带 `--shadow-e1`。

**为什么需要阴影**：`#ffffff` 卡片在 `#fafafa` 页面上只有 1.02:1，**看不见**。参考图用绿/青大色块分区，而本项目不允许品牌色，所以用阴影替代。

### 9.3 源名称大小写敏感

**决定**：规则镜像里 `MXdm` 和 `mxdm` 是两个请求，后者 404。

**拒绝了**：
- ❌ 大小写回退 —— 会把"镜像挂了"伪装成"规则解析失败"

**同类原则**：错误信息要能指出真正的原因，不能为了"顺手"而掩盖。

## 十一、Android 移植

完整技术细节在 [`docs/android.md`](../android.md)，这里只记**决定和拒绝了什么**。

### 11.1 TLS 用内置根证书，不用平台验证器

**决定**：`tls.rs` 用 `webpki-roots` 自建 `ClientConfig`，经 `tls_backend_preconfigured` 注入。

**为什么**：reqwest 的 `rustls` feature 在 Android 上走 `rustls-platform-verifier`，它要调 JVM 的 `TrustManager`；未初始化就发请求会**直接 abort 进程**（`Expect rustls-platform-verifier to be initialized`）。

**拒绝了**：

- ❌ **接入官方 AAR** —— 需往 Gradle 加 GitHub 上的 Maven 仓库，该仓库在目标网络下不可达；还要维护 Kotlin 组件与版本同步
- ❌ **改用 `native-tls`** —— Android 上引入 OpenSSL 交叉编译，破坏「一条命令出包」
- ❌ **去掉联网功能** —— 应用的核心就是从源取内容

**代价**：静态根证书列表，用户自建企业 CA 不被信任。对公网书源可接受。

### 11.2 PDF 降级到 4.10.38

**决定**：`pdfjs-dist` 从 6.4.299 降到 **4.10.38**。

**为什么**：6.x 用了 `Map.getOrInsertComputed`（Chrome 140+），目标设备 WebView 是 134，PDF 直接打不开。`legacy/` 构建也用了同类 API，polyfill 补不完。

**拒绝了**：

- ❌ **继续补 polyfill** —— 第一轮补了 `toHex`，第二轮又冒出 `getOrInsertComputed`，没有尽头
- ❌ **要求用户升级 WebView** —— 把风险转嫁给用户，部分设备无法升级

**代价**：失去 6.x 的 wasm/icc 渲染路径。**换来的是 4.x 自己对 `Uint8Array` 新方法做 feature-detect**，一行 polyfill 都不需要，且包体积小了约 115 KB。

### 11.3 窄屏保留侧栏，默认折叠成图标栏

**决定**：`< 719px` 时侧栏**不变成底栏**，只把默认状态改成折叠（56px 图标栏）。

**为什么**：四个入口都常用，底栏占用永久横向空间且改变应用视觉身份；而「折叠成 rail」是桌面**本来就有的机制**，只是默认值不同。

**拒绝了**：

- ❌ **底栏导航** —— 第一版实现过，被否：改变了原有设计
- ❌ **抽屉** —— 隐藏当前位置，且每次导航多一次点击
- ❌ **保持 208px 不折叠** —— 360px 屏幕上内容区只剩 152px，不可用

**细节**：用户手动展开过则尊重其选择（`readCollapsed` 先读 localStorage，无值才看视口宽度）。

### 11.4 全屏用 CSS 兜底

**决定**：先试 Fullscreen API，拿不到状态就用 `position: fixed` 的 CSS 伪全屏。

**为什么**：wry 的 Android 实现 `onShowCustomView` 第一行就是 `callback.onCustomViewHidden()`，`requestFullscreen()` **必然无效且不报错**（promise 照常 resolve）。

**拒绝了**：

- ❌ **不提供全屏按钮** —— 手机上横屏看视频是刚需
- ❌ **改 wry 源码** —— fork 上游 crate 的维护成本过高

**判据**：不能只看 promise 有没有 resolve，要看 `document.fullscreenElement` 是否真的存在。

### 11.5 封面限流用原子计数，不用 tokio 信号量

**决定**：`COVER_IN_FLIGHT: AtomicUsize` + `CoverSlot` 的 `Drop` 释放槽位。

**为什么**：`tokio` 在本项目是 **dev-dependency**（只有测试需要 runtime）。为一个限流器把它提升为正式依赖不划算。

**拒绝了**：

- ❌ **加 `tokio` 正式依赖** —— 为一个计数器引入整个运行时
- ❌ **不限流** —— 80 张卡片同时请求会把连接池占满，每张都等满超时

**注意**：这是本项目**唯一**允许忙等的地方，因为等待上限是一次封面下载，且在 worker 线程而非 UI 线程。
